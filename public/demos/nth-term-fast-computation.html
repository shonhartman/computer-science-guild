Linear Recurrences: Computing the N-th Term Fast

How to jump straight to the 1018-th term of a sequence like Fibonacci — without computing the 1018 − 1 terms before it.

1What is a linear recurrence?

A linear recurrence is any sequence where each value is a fixed linear combination of the previous d values. The number d is called the order of the recurrence.

a(n) = c₁·a(n−1) + c₂·a(n−2) + … + c_d·a(n−d)

Fibonacci is the simplest interesting example — order 2, both coefficients equal to 1:

F(n) = F(n−1) + F(n−2),   F(0) = 0, F(1) = 1

These show up everywhere each state depends on a bounded window of previous states: counting problems, dynamic programming, random walks, population models.

2Why the naive solution breaks down

The obvious approach computes every term one by one. For an order-d recurrence that costs O(d·N) — each of the N steps does d multiplications.

Fine for N = 10⁶. Hopeless for N = 10¹⁸: at a billion operations per second, the naive loop would run for roughly 30 years. The fast solvers below compute the N-th term in time logarithmic in N — a few hundred operations instead of a quintillion.

3The fast solvers

Matrix exponentiation — O(d³ log N)

Package the last d values into a vector, and express "advance one step" as multiplication by a fixed transition matrix. For Fibonacci:

F(n+1)F(n) = 1110 · F(n)F(n−1)   so   F(n+1)F(n) = 1110n · F(1)F(0)

Advancing N steps means raising the matrix to the N-th power — and powers can be computed by repeated squaring (binary exponentiation), exactly like fast exponentiation of numbers. Only log₂ N ≈ 60 squarings are needed for N = 10¹⁸. Each matrix multiply costs O(d³), giving O(d³ log N) total. For small recurrences like Fibonacci this is the simplest and most popular solution.

Fiduccia's algorithm — O(d log d · log N)

Fiduccia drops the matrix entirely. The recurrence becomes its characteristic polynomial (for Fibonacci: x² − x − 1), and computing the N-th term reduces to computing xᴺ mod (characteristic polynomial) — binary exponentiation again, but on polynomials of degree < d instead of d×d matrices. With FFT-based polynomial multiplication each step costs O(d log d) instead of O(d³), which is a huge win for high-order recurrences (d in the thousands).

Bostan–Mori — same asymptotics, faster in practice

Bostan–Mori (2020) is one of the fastest known general algorithms. It views the sequence as a rational generating function P(x)/Q(x) and extracts the N-th coefficient by repeatedly halving N, using the identity that multiplying numerator and denominator by Q(−x) makes the denominator a polynomial in x². Same O(d log d · log N) complexity as Fiduccia, but with a smaller constant — fewer polynomial multiplications per halving step. Think of it as the modern refinement of Fiduccia's idea.

4Where this shows up in CS

Domino tilings

Count the ways to cover a 2 × N board with 2 × 1 dominoes. The leftmost column is covered either by one vertical domino (leaving a 2 × (N−1) board) or by two stacked horizontal dominoes (leaving 2 × (N−2)). So:

T(N) = T(N−1) + T(N−2) — exactly the Fibonacci recurrence

Fibonacci heaps

The name comes from the analysis, not the implementation. The key lemma: in a Fibonacci heap, any node of degree k has at least F(k+2) nodes in its subtree. Because Fibonacci numbers grow exponentially (F(k) ≈ φᵏ/√5), a heap of n nodes can only contain nodes of degree O(log n). That bound on the maximum degree is precisely what makes decrease-key run in O(1) amortized time and gives the heap its famous amortized bounds.

And beyond

Counting walks of length N in a graph (adjacency matrix to the N-th power), analyzing linear-feedback shift registers in cryptography, probability of states after N steps of a Markov chain, and squeezing dynamic programming solutions past tight time limits in competitive programming.

5The takeaway

The skill worth keeping isn't the algorithms — it's the recognition. When each state depends on a fixed number of previous states, the problem is a linear recurrence, and an O(N) solution can usually become O(log N). Matrix exponentiation covers 95% of real cases; Fiduccia and Bostan–Mori exist for when the order d gets large.

You probably won't reach for these in everyday web development. You will meet them in competitive programming, algorithmic interviews, DP optimization, graph problems, cryptography, and mathematical software.

Appendix: matrix exponentiation in ~20 lines

const MOD = 1_000_000_007n;

function matMul(A, B) {          // 2x2 matrices of BigInt
  return [
    [(A[0][0]*B[0][0] + A[0][1]*B[1][0]) % MOD, (A[0][0]*B[0][1] + A[0][1]*B[1][1]) % MOD],
    [(A[1][0]*B[0][0] + A[1][1]*B[1][0]) % MOD, (A[1][0]*B[0][1] + A[1][1]*B[1][1]) % MOD],
  ];
}

function fib(n) {                // F(n) mod 1e9+7, n as BigInt
  let result = [[1n, 0n], [0n, 1n]];   // identity
  let base   = [[1n, 1n], [1n, 0n]];   // transition matrix
  while (n > 0n) {
    if (n & 1n) result = matMul(result, base);
    base = matMul(base, base);         // repeated squaring
    n >>= 1n;
  }
  return result[1][0];                 // F(n)
}

This exact code powers the demo above. Sixty squarings instead of a quintillion additions.
